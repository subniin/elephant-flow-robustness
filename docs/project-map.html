Elephant Flow Robustness

flow의 처음 N개 데이터 패킷으로 elephant(바이트 상위 flow)를 미리 맞출 수 있는지, 그 성능이 날짜·데이터셋이 바뀌거나 임계값 정의가 바뀌어도 유지되는지를 재는 프로젝트입니다. 이 페이지는 코드, 데이터, 실험, 지금까지 나온 결과를 한 장으로 정리합니다.

1. 데이터가 흐르는 길

점선 상자는 파일, 실선 상자는 코드입니다. 모든 모듈은 src/flowpred/에 있고 PYTHONPATH=src로 실행합니다.

2. 핵심 정의

flow

한 pcap 안의 단방향 IPv4 TCP/UDP 5-tuple. idle timeout 없음. 데이터 패킷은 페이로드가 0보다 큰 패킷입니다.

특징 (처음 N개 데이터 패킷)

proto, src_port, dst_port, n_seen과 패킷 크기 plen_1..n, 도착 간격 iat_1..n-1. 총 열 수는 n=0이면 3, 아니면 2n+3. pkt_count와 byte_count는 정답이라 특징에서 뺍니다.

elephant 임계값

기본은 train 구간 바이트 상위 1%(bytes_pct, p=0.01). 상위 10%는 데이터 패킷이 n개 미만인 elephant가 절반이라 정답이 특징에 들어 있어 기본에서 뺐습니다. 고정 바이트, 패킷 수 기준도 선택할 수 있습니다.

평가

시간순 70/30 분할 또는 별도 test CSV. 정밀도, 재현율, F1, F1 95% 신뢰구간(test 복원추출 200회), 트래픽 커버리지, flow table 감소 배수. elephant를 short/long, TCP/UDP로 나눈 층화 recall도 냅니다.

3. 질문과 실험 진행 상황

차별점은 두 가지입니다. (1) 날짜·데이터셋을 넘는 일반화, (2) 임계값 정의·크기에 따른 민감도. 조기 중단 규칙은 프로젝트가 끝난 뒤 추가할지 정할 후보입니다.

완료

E1–E3 기본 베이스라인

RandomForest, 헤더만 쓴 기준선(n=0), n ∈ {0,1,3,4,10} ablation. 2012와 2026 각각 한 trace 안에서 평가했습니다.

예비

R2 날짜 간 일반화

2012 ↔ 2026 양방향 완료. 방향에 따라 성능이 크게 다릅니다. 날짜가 둘뿐이라 시간과 수집 환경 효과를 구분하지 못합니다.

미착수

R1 임계값 민감도

상위 10%·1%·0.1%와 고정 100KB 비교. 기본값 선정 때 10%의 누설만 측정했습니다.

대기

R3 MAWI ↔ CAIDA

CAIDA 승인 전이라 시작하지 않았습니다.

미착수

R4 특징 기여

헤더·크기·타이밍 특징 묶음(FEATURE_GROUPS)별 기여도.

후보

조기 중단 규칙

확신이 서면 패킷 N개를 다 기다리지 않고 판정하는 규칙. 프로젝트 종료 후 결정.

2026 trace는 패킷이 4.7억 개라 flow 해시 샘플링 10%로 줄였습니다. 샘플링은 비율 지표(F1 등)에는 영향이 없다고 보지만 flow table 감소 배수 같은 절대 규모 지표는 sample_rate로 보정해서 읽어야 합니다. train과 test의 sample_rate가 다르면 오류를 냅니다.

5. 지금까지 나온 결과

n(처음 몇 개 데이터 패킷을 쓰는가)에 따른 F1입니다. 점에 마우스를 올리면 값이 나옵니다.

n=10은 해석하면 안 됩니다. test elephant의 11–24%가 데이터 패킷 10개 미만인 flow라 정답이 특징에 그대로 들어 있습니다(음영 구간). 날짜 간 두 선은 임계값을 8,909B로 같게 맞춘 값이고, n=4의 날짜 간 값만 시드 5개 평균입니다. 나머지는 시드 1개입니다.

n이 커질수록 F1 증가

같은 날짜 안에서 n=0(헤더만) 0.17–0.28, n=4 약 0.68. 헤더만으로는 부족하고 초반 패킷 크기와 간격이 정보를 줍니다.

날짜 간 성능은 방향마다 다름

n=4에서 2012로 학습해 2026을 맞히면 0.29, 반대로 2026으로 학습해 2012를 맞히면 0.64. 시드 표준편차는 0.006–0.016입니다.

UDP만의 문제는 아님

2012 elephant는 TCP 93%, 포트 80이 79%. 2026은 UDP 30%, 포트 443이 85%. UDP elephant는 양방향 모두 recall이 0–0.11이지만, 2012 → 2026은 TCP만 봐도 0.22로 2026 → 2012의 0.53보다 낮습니다. 원인은 아직 모릅니다.

7. 작업 방식

spec 작성→ 구현 + 테스트→ gate (pytest)→ verifier 판정→ 커밋 · push

동작을 바꾸거나 파일을 둘 이상 고치는 작업은 먼저 harness/specs/에 수용 기준을 쓰고, 별도 verifier가 기준마다 통과 여부를 판정합니다. 완료는 gate 결과로 정하고 자기 보고로 정하지 않습니다.

한계: MAWI 두 날짜(2012, 2026)와 단일 수집 지점뿐이고 한 날짜당 15분입니다. 날짜 차이의 원인이 시간인지 환경인지는 단정할 수 없습니다. 위 수치는 모두 예비 결과입니다.
